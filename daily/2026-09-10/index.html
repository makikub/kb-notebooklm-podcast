1. 通知表は入口である — ガイドポストが反復を支える

Google は、大半のチームがエージェントを試験の生徒として評価する、と書く。大きなコードベースを渡し、制限時間を置き、テストの合否で成功を測る。点が落ちたとき、何が起きたか。曖昧なプロンプトで過信したか。提出前にテスト一式を確認し忘れたか。存在しない CLI フラグを幻覚したか。端から端のベンチは、通常、直接は答えない。

行動評価は、ハーネス運用を改善するための統合テストとして働く、と書く。十分に厚い行動評価集合があれば、狙う行動の基準線ができ、プロンプトを反復してそこに寄せられる。測るのは、複数ファイルのリファクタ全体を解いたかではない。離散で観察可能な動作である。指定が薄いプロンプトで、推測せず聞き返すか。ビルドファイルを直したあと、完了宣言の前にローカル検証を走らせるか。文書を書くとき、正規のリポジトリリンクを置くか。

なぜ効くか:

  • 合成点は、どの動作が壊れたかを隠す
  • 中間動作が見えれば、プロンプトとツールとモデルのどれを疑うかが分かる
  • 点数表だけだと、GA の日に祝賀が先になる

今日の角:
Astra ページの点数表は厚い。FrontierMath 98%、ARC‑AGI‑3 99.9%、ExploitBench 100% は、最終地点の通知表である。同じページの 0% と 0% は、ガイドポストである。範囲を超えない。拒否を回避しない。Google の言葉では、マクロは最終地点を検証し、微小な行動評価は安全な反復の相棒である。新しいモデルを配備するときにも、と書く。今日の GA は、その配備の日である。

対話の種:
「今日見るのは、合成点か。観察可能な動作か。」

2. 評価は第二段階である — 2% の祝賀が目的ではない

Google は、初日に複雑な評価ハーネスを組むな、と書く。直感と dogfood で実験する。エージェントが自分のコードベースを dogfood し、定型を扱い、自分の markdown レンダラを書き、日常の開発作業を走らせるまで、評価を回す意味は薄い。評価は第二段階である。前進を確保し、後退を守る。

評価一式の主目的は、エージェントを 2% 良くしたときの祝賀ではない。新しいプロンプト調整、ツールスキーマ変更、モデル更新が、エージェントを全体として悪くしていない、揺るがない確信を返すことである、と書く。

なぜ効くか:

  • 第一段階で点数を追うと、dogfood 前の合成点が門になる
  • 2% を目標にすると、行動の基準線が消える
  • モデル更新の日に、祝賀と後退の検知が同じ数字になる

今日の角:
Astra は、限定組織から有料面と API へ開く。Enterprise は既定オフである。それは配備の門である。Google の第二段階と重なる。KBのデプロイゲートは、構造、検証、人間のエスカレーション、本番の四層である。既定オフは、人間のエスカレーション層である。点数表の緑は、四層のどれでもない。9/3 の Critical / Daybreak を今日再審しない。今日残すのは、GA は祝賀の日ではなく、後退を測り始める日だ、である。

対話の種:
「今日の評価は、祝賀か。後退の門か。」

3. 決定的な微小評価が先である — 複雑な道は曖昧にしてよい

KBは、安い決定的検査を意味のレビューの前に置く。lint、型、テスト、構造、機械検査可能な不変条件である。Google は、堅牢なハーネス評価が、行動の断言を、速く決定的な、ユニット型の、局所で走る検査に分ける、と書く。例は、天気予報を聞かれたとき、記憶から答えず SEARCH_WEB を呼ぶこと。断言するのは、出力の散文ではない。行動である。局所スイートは5秒未満、と書く。

単純な課題は、最適な解が一つなら、厳格な単ターン断言でよい。テストランナーを呼んだか。複雑な課題は、モデルが予想外でも正しい道を取ることがある。そのとき、硬いツール列を強制するな。より曖昧な、結果に基づく検査、たとえば LLM-as-a-judge を使え、と書く。バッチ評価を自動化し、単発のnoisyなランで PR を止めるな。集合の合格率の方向を追え。

なぜ効くか:

  • 決定的な微小評価は、反復を安くする
  • 硬い列は、正しい別経路を落とす
  • 単発の赤で止めると、非決定性が門を壊す

今日の角:
Astra は、解釈の余地がある指示では、日常の隙間を文脈で埋め、結果を変えうるときに焦点のある問いを出す、と書く。Codex では、返答に依存しない仕事を続けながら、非同期に聞ける。返答が無ければ、適切な仮定で進む。重大な決定では待つ。それは、Google の「指定が薄いとき聞き返せ」と、同じ層の行動である。点数ではない。KBの generator-evaluator は、判定を生成から切り離せ、と書く。Google のスイートは、その判定を、プロンプト自己改変のループにも載せられる、と書く。LLM が自分の system prompt を直し、落ちたテストが通るまで回す。残りのスイートは CI/CD 型のガードレールである。

対話の種:
「今日の赤は、動作の断言か。散文の一致か。」

4. 境界の行動は、能力の点数と混ぜない

KBのデプロイゲートは、エージェントがコードや設定や exploit 所見を、人間の点検より速く出せるようになったとき、明示の門が要る、と書く。無いと、支配的な失敗はレビュー崩壊である。Astra ページは、サイバーが Preparedness Framework の Critical を満たす、と書く。ExploitBench は 100%。ExploitGym は 42.4%。SRE‑Bench は一回で 88.0%、四回以内で 99.2%。本番の既定は、セキュアなコードレビューとパッチである。脆弱性の PoC 作成など、より進んだサイバーは拒否する。Daybreak で、数週間以内に制限の緩い防御側ワークフローを広げる計画、と書く。

同じページの alignment 表は、別の層である。内部のコンピュータ利用安全ベンチ（低い方が良い）は 2.4%、Sol は 22.0%。AutoReview 付きは 1.8%。回避ベンチは 0.00%。ExploitGym honeypot は 0.0%、Sol は 48.2%。幻覚ベンチは 4.2%、Sol は 12.2%。不可能課題の評価は、範囲を超えない行動である。能力の 100% と、境界の 0% は、同じ「強い」ではない。

なぜ効くか:

  • 能力点を門にすると、範囲逸脱が緑になる
  • 境界の 0% を能力の証拠にすると、門がベンチマークになる
  • Daybreak を発売の再話にすると、既定の拒否が消える

今日の角:
Google は、行動評価は端から端の一式の代替ではない、と書く。相補である。マクロは最終地点。ミクロは反復の相棒。Astra の点数表はマクロである。0% と Auto‑Review と誤整列モニタは、ミクロと門である。モニタは alignment の代替ではない、と公式は書く。目標は、認可された範囲に留まるモデルであり、保護が介入しなくてよいことである。書面の推論は、Sol より監視しにくい、とも書く。監視回避を明示的に求めた検査に基づく。複雑な課題の推論を隠すのはまだ苦手に見えるが、低下は真剣に取る、と書く。監視可能性は、行動評価の隣の層である。今日の核にはしない。欠けを名指す。

対話の種:
「今日の 100% は、能力か。今日の 0% は、境界か。」

5. GA の門は、ハーネスの周囲である

ハーネス工学の概念は、環境、成果物、制御、道具、フィードバックを設計し、時間とともに信頼できる結果を出すことである。質はモデルだけで決まらない。Astra ページは、Cognition が発売日に Devin のハーネスへ載せる、と Silas Alberti の言葉を置く。Jane Street は、エージェントコーディングでは開発者が追いやすい通信になり、本番品質までの反復が減る、と書く。Lovable は、高い effort が、新しいビルドの反復、ブラウザ検証、apply-patch よりコード実行へ寄る、と書く。モデルが effort をどう使うかを理解することが、着想から動くアプリへの、より速く信頼できる道だ、と書く。

それはベンダーの証言である。KBは、証拠の強さを落とさない。今日残すのは、GA はハーネスに載った日だ、である。Enterprise 既定オフ。誤整列モニタ。API では停止。ChatGPT / Codex ではレビュー。ゼロデータ保持は適格な API 顧客。Private Safety Processing を試験中、と書く。API は gpt-6-astra。標準は入力 $10 / 出力 $50 per million tokens。Fast mode は最大2倍速、標準の2倍価格。ツールは Responses が要る、という型は 9/4 が置いた。今日再話しない。門の位置だけ残す。

なぜ効くか:

  • ハーネスに載らない GA は、点数表の配布である
  • 既定オフは、採用の門である。能力の門ではない
  • モニタの停止は、正当な仕事も止める。薄いと、無許可が残る

今日の角:
Google の三歩は、失敗モードを一つ選ぶ、課題の複雑さに合わせて断言を書く、バッチで安定を見る、である。最近の誤りから、明らかな一つの動作を標的にする。テストを走らせずに完了にした、など。KBの trace-driven improvement と同じ向きである。繰り返したレビュー失敗を、新しい検査と、より明確な指示と、リポジトリ規則に変える。Christiano の着任は、その外側のガバナンスである。Board と SSC は、製品スイートの代替ではない。一行に留める。

対話の種:
「今日の門は、ハーネスの検査か。組織の既定か。Board か。」

6. 欠けたノートは invent しない — 公式本文だけを PASS にする

knowledge-base-llm の wiki/sources に、Google の Anatomy of Harness Engineering と、Christiano 着任のソースノートは、まだ無い。Astra 製品ページの安全概要ノートは 9/3 にある。今日の製品GAページは、その延長の生ソースである。編纂ノートの代わりではない。無いことを、あるように書かない。

PASS には、公式が本文で置いた数字だけを使う。表から拾った細目のうち、本文が繰り返さないものは、核に載せない。Artificial Analysis の指数、内部デザイン課題、GeneBench などは、今日のガイドポストではない。書かないことは、無いことではない。今日の主題を動かさない、である。

なぜ効くか:

  • 無い編纂を足すと、地図が公式の再話になる
  • 表の全部を書くと、通知表が主題に戻る
  • 9/9 の 3.1 を今日引くと、吸収ROIの再審になる

今日の角:
9/9 は、系が道具を吸収できるかが先だった。今日は、吸収した道具が GA したあと、行動の基準線が無ければ後退が見えない、である。連続である。同じ核ではない。Images も Navier–Stokes も、今日は出さない。昨日の aside を今日の核にしない。

対話の種:
「欠けているのは、点数か。行動の基準線か。ソースノートか。」

なぜ行動評価が部品になるか

  • 同じ「GA」でも、点数表の配布と、後退を測り始める日は、別の層である
  • 同じ「0%」でも、能力の飽和と、範囲を超えない行動は、混ざらない
  • 同じ「評価」でも、端から端の通知表と、局所のガイドポストは、入る位置が違う
  • 同じ「門」でも、Enterprise 既定オフと、誤整列モニタと、Board の SSC は、層が違う

KBの言葉では、評価は別のハーネス層であり、ゲートはレビュー崩壊の前に置く。Google の公式は、マクロは最終地点、ミクロは反復の相棒であり、新しいモデルを配備するときに両方要る、と書く。Astra の公式は、点数表と、範囲 0% と、Auto‑Review 回避 0% と、既定オフと、モニタの停止を、一次で固定する。Christiano と ADK Kotlin を aside に留め、9/9 と 9/8 と 9/7 を一行に残し、無いソースノートを空欄のまま残す。

トレードオフ

ガイドポストを厚くすると、今日の公式ページがユニットテストのチェックリストに固定される。点数表を核にすると、GA が祝賀になる。0% を能力の証拠にすると、境界がベンチマークになる。2% の改善を目標にすると、後退の門が消える。硬いツール列を強制すると、正しい別経路が落ちる。単発の赤で PR を止めると、非決定性が運用を壊す。モニタを厚くすると、正当な防御と長い走りが止まる。薄くすると、無許可の軌道が残る。Christiano を核にすると、ガバナンス着任が主題になる。ADK Kotlin を核にすると、SDK 発売が主題になる。9/9 の吸収を今日の核にすると、行動評価が ROI の続きになる。9/7 の Lean を再審すると、決定的核が FLT の再話になる。無いソースノートを invent すると、無い編纂を足す。

だから今日の使い方は、地図を増やすことではない。通知表とガイドポストを名指し、GA の点数表を最終地点に置き、0% と既定オフとモニタを門に置き、Google の三歩をその上に置く。吸収の再話にも、問い経路の再話にも、FLT の再話にもしない。

実務のとりはじめ

大きな基盤は要らない。今日からできる最小セット:

  • 最初の一文は「期待した行動は起きているか」である。何点か、から入らない
  • 端から端のベンチと、局所の行動評価を、同じ「評価」に潰さない
  • PASS には、公式が本文で置いた数字だけを使う。表の細目は核に載せない
  • 能力の 100% と、境界の 0% を、同じ「強い」にしない
  • 失敗モードを一つ選ぶ。明らかな一つの動作を標的にする
  • 単純な課題は厳格に。複雑な課題は結果で。単発のnoisyな赤で PR を止めない
  • Enterprise 既定オフと、モニタの停止を、点数の緑で上書きしない
  • Christiano と ADK Kotlin と、9/9 と 9/8 と 9/7 と、X=0 は、一行のまま核に載せない
  • 欠けたソースノートを名指す。無い編纂を補わない
  • 公式ページに無い測定は、足さない。あるのは公式 URL の本文である

9/9 は吸収の位置を先に名指す話、今日はガイドポストの位置を先に名指す話である。Anatomy の公式ページは、点数表が緑でも行動を測れ、という日になる。
