## なぜ評価信頼性地図が部品になるか

- 同じ「強いモデル」でも、生成する側と、核で通す側は、別の層である
- 同じ「複数エージェント」でも、会話で並走する系と、DAG で並走する系は、状態の持ち方が違う
- 同じ「レビュー」でも、人が 13百万行を読むことと、核が論理を検査することは、混ざらない
- 同じ「ゲート」でも、Astra のモニタ停止と、Lean の合格は、入る位置が違う

KBの言葉では、評価は別のハーネス層であり、決定的検査を先に置き、生成と判定を分け、痕跡を規則に戻す、という地図である。9/4 は、人がまだレビューできるかだった。今日は、人が同じ速さで審さない成果物を、独立の核が十分だと判定できるかである。公式の型は、既知証明の端から端までの計算機検査、Prove2Me の DAG、Lean の三公理、Mathlib 文との一致、約11日／数十エージェント／約60億トークン／Fable 5.1 相当を一次で固定し、Lyria と `ant apply` を aside に留め、Astra を一行に残し、Cursor の声明と X の取得を、空欄のまま残す。

## トレードオフ

核を厚くすると、人が読まない行が増える。公式自身が、この証明は必要以上に長いだろう、と書く。DAG を厚くすると、経路が足場に固定される。足場が無いと、状態喪失で折れる。自動形式化を解説の代わりにすると、意図の負債が残る。公式は置き換えるな、と書く。査読を核に委譲すると、人が経路を選ぶ技量が削れることがある。Lyria を核にすると、創作面が主題になる。`ant apply` を核にすると、資源 IaC が検証の話になる。Astra を今日の核にすると、評価層が認知負債の続きになる。巻き戻しの不在を声明にすると、無い文を足す。

だから今日の使い方は、地図を増やすことではない。独立の核と、外に出た DAG と、人が同じ速さで審さない負荷を名指し、FLT の形式化をその上に置く。新定理の再話にも、9/4 の再話にもしない。

## 実務のとりはじめ

大きな基盤は要らない。今日からできる最小セット:
- 合格条件を、同じエージェントの一目ではなく、外の検査器で一文にする
- 長い並走を許すなら、次の仕事を決める面を、会話ではなく外のグラフか成果物に置く
- PASS には、合格条件に対応する開かれた証拠を要求する。行数の多さは証拠にしない
- 人間向けの解説と、核が通した成果物を、同じ門にしない。公式は置き換えるな、と書く
- 折れた走りを、核が残した行と、人が残したい教訓に分ける
- Lyria と `ant apply` と、9/4 の Astra と、X=0 は、一行のまま核に載せない
- Cursor の巻き戻し声明は、無い。補わない
- 公式ページに無い GitHub URL は、足さない。あるのは `anthropics/fermats-last-theorem` である

9/4 は理解と再開の位置を先に名指す話、今日は核と DAG の位置を先に名指す話である。既知の証明を計算機が検査した公式ページは、評価を別層に書け、という日になる。
