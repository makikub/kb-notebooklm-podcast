KBの能力投資地図は、計算の経済は能力投資の数字である、と書く。顧客の回収率ではない。証拠品質は、公式が置いた文だけを硬い制約に使え、と書く。今日の公式が固定するのは、五つの比較である。40% は、既定の典型仕事対 Opus 5 である。20% は、入出力の定価対 Opus 5 である。60% は、キャッシュ読み対 Opus 5 である。30% は、出力の速さ対 Opus 5 である。2.5 倍と $8 / $40 は、Fast mode 対 通常の Opus 5.5 である。五段を一つの「四割安い旗艦」に潰さない。仕事あたりの実費の分布も、採用後の回収率も、本文には無い。無い回収率を invent しない。欠けを名指す。

なぜ効くか:
- 40% を定価の割引にすると、20% の $4 / $20 が消える
- 20% を仕事の費用にすると、トークン数の減少が消える
- 60% を全トークンの割引にすると、キャッシュ読みだけが大半だ、という限定が消える
- Fast mode の $8 / $40 を既定にすると、2.5 倍の速度が通常料金になる
- 五時間上限の引き上げを、API の $4 に足すと、購読の枠が定価になる

今日の角:
購読の五時間上限と、保存できるリセットは、API の定価ではない。別の段である。本文は、上限が何倍になったかを書かない。無い倍数を invent しない。9/22 の速い変種は、速度も価格も二倍、だった。今日の Fast mode は、速度が最大 2.5 倍、価格が $8 / $40 である。同じ「速い別料金」に見える。同じ数字ではない。昨日の二倍を、今日の証拠にしない。

対話の種:
「今日の四割は、定価か。キャッシュ読みか。既定の典型仕事か。Fast mode か。」

## 2. 旗艦の段と、中段の半額は、同じ段ではない

## なぜ段の名前が部品になるか

- 同じ「安い」でも、仕事の 40% と、定価の 20% と、キャッシュ読みの 60% と、Fast mode の $8 / $40 は、比較対象が違う

40% を定価の割引にすると、20% の $4 / $20 が消える。20% を仕事の費用にすると、トークン数の減少が消える。Fast mode を既定にすると、$8 / $40 が通常料金になる。50% を旗艦の 40% に足すと、Sol と Luna が旗艦のセールになる。きのうの $4 / $20 を今日の Sol に残すと、旧プロモが新定価になる。Fable 級を全行の首位にすると、Astra が上の行が消える。66.4% からセーフガードの注を外すと、無保護の点になる。54.4% と 54.6% を一つにすると、effort が消える。33.2% を 40.0% の隣に置くと、相手が Opus 5 のまま Opus 5.5 が負ける。60.5% を 81.8% と比べると、条件の違う OSWorld が一つの順位になる。保護の類を値引きにすると、Opus 4.8 への戻りが価格になる。LSVP を核にすると、9/18 が主題になる。Grok Bot の $0.20 を Luna に足すと、運用がトークン定価になる。9/22 の同じ単価を足すと、今日の値下げが長い走りの続きになる。無い点と、無い wiki と、500 のページを埋めると、無い測定が生まれる。

だから今日の使い方は、地図を増やすことではない。段の名前を残す。仕事の四割と定価の二割とキャッシュの六割を混ぜない。旗艦と Sol と Luna と Astra を混ぜない。表の effort と既定の effort を混ぜない。二つの公式の仕事あたり費用を一つの順位にしない。保護とサポート事例は一行に残す。
