## なぜ職場データエージェントと統治分析が部品になるか

- 同じ「聞けば答え」でも、承認された店と、開いた倉庫は、入口が違う
- 同じ「文脈」でも、プロンプトの用語と、共有の意味層は、残る位置が違う
- 同じ「権限」でも、Plugins の役割と、表／行／列と、情報隔壁は、層が違う
- 同じ「根拠」でも、追問いの見直しと、表への細かい引用は、粒度が違う
- 同じ「職場のデータ」でも、倉庫コネクタと、ホスト済み金融データと、既存購読は、店が違う

KBの言葉では、会社脳は権限と来歴と有効期間を持ち、証拠は主張の支えを書き、ゲートは生成の前に来る。OpenAI の Data agent 公式は、承認ソースと、意味層と、既存の表／行／列と、根拠の見直しと、更新できるダッシュボードと、承認した行動を、一次で固定する。Financial Services の公式は、ホスト済み金融データと、細かい引用と、entitlement と、情報隔壁と、社内テンプレートと、適格機関を、一次で固定する。Habitat と Gemini Windows を aside に留め、週末のフロンティアを二次に残し、9/11 と 9/10 と 9/9 を一行に残し、無いソースノートを空欄のまま残す。

## トレードオフ

平文を厚くすると、今日の公式が「SQL を書くな」チェックリストに固定される。意味層を抜くと、NL が倉庫を壊す。権限をプロンプトに落とすと、表／行／列が消える。ダッシュボードの共有を役割の外へ出すと、行制限が漏れる。倉庫コネクタとホスト済みデータを同じ店にすると、縦作業場が一般化する。引用を見た目のブランド指針にすると、根拠がデザインになる。Habitat を核にすると、保存工学が主題になる。Gemini を核にすると、デスクトップが主題になる。週末の談義を一次にすると、職場データが消える。9/11 のコーディネータを今日の核にすると、データエージェントがループの続きになる。無いソースノートを invent すると、無い編纂を足す。

だから今日の使い方は、地図を増やすことではない。承認された店を平文の前に置き、意味層を共有定義として名指し、権限をクエリと一緒に歩かせ、根拠を共有の条件にし、倉庫とホストと購読を分ける。コーディネータの再話にも、行動評価の再話にも、ストレージ工学の再話にもしない。
