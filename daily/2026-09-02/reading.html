親が分解する。検証だけが狭い割り

KBはオーケストレータを、平たい言葉で置きます。親エージェントかワークフローエンジンが、仕事を部分に分けます。境界のある下位を渡します。結果を集めます。次を決めます。製品の仕事に直感的なのは、プロジェクト管理に似るからです。一人の所有者が分解し、委任し、点検し、統合します。

Fable 5.1 の38時間引用は、親の型です。診断し、訂正し、6本を並列に出し、朝に統合します。動的ワークフローの地図も同じ棚です。Claude がオーケストレーションのスクリプトを書き、並列の下位を扇ぎ、進捗を会話の外に残します。親の指示流れです。バスではありません。Managed Agents も、リードが専門家へ委任する hosted の親です。型はFAQのままです。安く長くなっただけです。

地図は、「役割を全部別体にする必要はない」と先に書きます。よくある実務は、検証だけを分けることです。本体が計画し実装する。検証役が明示基準で見る。親か本体が、受け、直し、再試行を決めます。generator-verifier の輪です。TAKT もこの棚に近いです。YAML で段と遷移を書き、plan / implement / review / fix を中央が回します。並列のレビューがいても、遷移は中央です。純粋なバスではありません。

バスは親が呼ばない。高リスクは契約

メッセージバスは、事象駆動です。親が「レビューしろ」と言う流れではありません。pr_opened、ci_failed、security_alert を公開します。関心のある体が拾います。違いは体の数ではありません。制御の流れです。オーケストレータは直接の指示。バスは公開された事象。頭のモデルは、管理者対共有のインシデント板です。

製品開発では、バスは本体になりにくいです。本体はオーケストレータかエージェントチーム。バスは CI、PR、障害、リリース、ドキュメント、警報の周辺です。聞き役は要ります。ただし一人の思考エージェントが while true で座ることではありません。フック、webhook、キュー、pubsub、cron、薄い常時ワーカーです。インフラです。

きれいに分解できるなら、オーケストレータ＋下位から始めます。委任する仕事が高リスク、検証しにくい、権限が広いなら、明示の委任契約を足します。権限の範囲。監視の間隔。検証成果物。エスカレーション規則。同じ面が繰り返し、人間の中継が隘路なら、名前のある永続ロールへ移します。書いた責任、直接の宛先、共有タスク、状態と引き渡しの成果物です。Memory と Dreaming は、走を越えた経験の共有です。共有メモリの統治は、仕事の分解と同じ太さになります。

長い地平は、割り方を消さない

Fable 5.1 は脆弱性の発見を許します。exploit の開発は許しません。同じ重みでも、面ごとに箱が違います。Mythos は trusted access です。EFS は顧客側の箱です。これは昨日の梯子の再話ではありません。今日の契約の面です。alignment 節が、長い文脈と多エージェントへの見通しが薄い、と書くのも、同じ角です。扇げる幅が広がったとき、見える位置を契約に残します。

38時間の無人走は、永続ロールの証明ではありません。一回の親が、進捗を外に残して扇いだ例です。永続ロールが要る合図は、同じ面が繰り返し、人間の中継が詰まっていることです。長い走りが安くなったことと、混ぜません。キャッシュ単価は、親を長く走らせやすくします。典型25%、高エージェント45%は、公式の目安です。長く安くなると、割らない誘惑が強くなります。だから今日、FAQを先に読みます。

よい読みは、体の数で語らないことである。親が次を決め、検証だけを割り、緩い反応はバスに出し、高リスクは契約に残す。38時間と6並列はパートナー引用に留め、Gemini の映像数字と Cursor の不在は一行に残す。発売の再話にも、昨日の梯子の再話にもしない。
