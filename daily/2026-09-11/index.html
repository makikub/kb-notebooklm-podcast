1. コーディネータは書かない — 詰まない親が本体である

Cursor は、コーディネータ自身はコードを書かない、と書く。計画し、実装するエージェントへ渡し、終わった仕事を点検へ戻す。委任するから詰まない。常に指示へ応答する。Projects は左ナビから入り、必要な数だけ下位を並列に起こす。

KBのハーネス風景は、役割の分離を五次元の一つに置く。全部を一つのチャットに載せると、計画と実装と点検が同じ手になる。コーディネータが書くと、親が詰まる。親が詰まると、指示の入口が消える。

なぜ効くか:

  • 書く親は、長い移行の途中で応答を失う
  • 委任する親は、点検の位置に留まれる
  • 体の数ではなく、誰が次を決めるかが先に見える

今日の角:
Agents API も、同じ層を製品にする。ハーネスがモデルとツールのループを持つ。アプリは仕事を送り、結果を受ける。下位への分割と、走行中の操舵は、管理ハーネスの中にある。9/2 の「親が分解する」を今日再審しない。今日残すのは、書かない親が、製品の入口になった、である。

対話の種:
「今日の親は、書いているか。委任しているか。」

2. 共有コンテキストは、毎回のオンボーディングを終わらせる

Cursor は、タスクのたびにエージェントをオンボードするな、と書く。Project は、クラウドとローカルの全マシンへ同期するファイル集合を持つ。エージェントは調査と成果物を足す。コードベースの学びと、好みの進め方も残る。あるエージェントがサービスの試し方を見つければ、以後のエージェントは同じ指示を使える。共有コンテキストは Project とともに育ち、コーディネータを強くする、と書く。

機能の型では、最初の調査が共有コンテキストへ残る。フィードバックのたびに、構成と好みを学ぶ。出荷後も、同じ Project が元の判断の全文脈でログとバグを見る。移行の型では、安全な型を一度決め、それをコードベースへ段階で適用する。ガーデニングでは、同じ誤りを二度見たら lint になる。学びが、次の PR の門になる。

なぜ効くか:

  • 毎回のオンボードは、同じ試し方を何度も発見する
  • 残らない学びは、コーディネータを強くしない
  • 好みがファイルに無いと、各下位が別の仕事の仕方をする

今日の角:
KBのオンボーディング地図は、ドメインKBとコードベースを、次が使える形で残せ、と書く。文脈管理は、全部を毎回載せるな、と書く。Agents API のスキルと、capability directories と、以前の仕事の要約は、同じ層である。Genkit の段階開示は aside である。表だけ先に載せ、本体は要るとき開く。今日それを核にしない。欠けを名指す。今日の核は、共有ファイルが、オンボードの代わりになる、である。

対話の種:
「今日残すのは、プロンプトか。次が使えるファイルか。」

3. セッションは耐久である — ラップトップを閉じても止まらない

Cursor は、Project はクラウド上の専用計算機で走る、と書く。ラップトップを閉じても止まらない。手元より多い下位を並列に走らせる。手元の検証が要るときだけ、ローカルを起こす。仕事は単一チャットより長く生きる。何ヶ月も文脈を保つ、と書く。

Agents API は、セッションを耐久の実体として置く。状態を残すので、会話文脈を組み直さずに続けられる。中断した場所から再開する。圧縮は製品側である。ホスト側サンドボックスは、存在するあいだファイルをターンをまたいで残す。/workspace/outputs は、ターン完了時に不変の成果物になる。サンドボックスが切れても、その写しは残る。無通信が1時間続くと、サンドボックスは消えうる。ストリームを閉じても仕事は止まらない。セッションを消すと、掃除を頼む。

なぜ効くか:

  • チャット寿命の仕事は、移行もガーデニングも持たない
  • 耐久が無いと、共有コンテキストは毎回消える
  • 閉じても止まらない計算機が無いと、艦隊は手元の上限になる

今日の角:
KBのハーネス風景は、セッションをまたぐ継続を次元に置く。今日の二本の公式は、それを製品にする。Cursor は Project の計算機である。OpenAI は Session である。層は近い。同じ製品ではない。データ所在は米国のみ、ZDR は無い、は Agents API の門である。自己ホストでも ZDR にはならない。クラウド既定と、所在の門を、同じ「耐久」にしない。

対話の種:
「今日の耐久は、Project の計算機か。Session か。成果物の写しか。」

4. 購読は、プロンプトを待たない

Cursor の購読は、Slack、スケジュール、全 PR である。検知した信号で動く。促を待たない。バグ報告チャンネルを指せば、届くたびに委任が始まる。ガーデニングは、新規 PR を追い、Slack のバグを聴き、スケジュールで走る。終わらない仕事の入口である。

Agents API は、ストリームと webhook を置く。ストリームは走行中の詳細である。webhook は、ストリームを開けずに状態変化を受ける。自己ホストでは、environment_connection の required action で、実行器の接続を起こす。関数道具のハンドラが居ないと、エージェントは結果待ちのまま残る。

なぜ効くか:

  • 促待ちの親は、届いたバグを見逃す
  • 信号で委任が始まると、ガーデニングが本体になる
  • webhook が無いと、耐久セッションは開いた接続に縛られる

今日の角:
Challenge の事象駆動は aside である。呼出し連鎖では遅延が足し算になる。話題バスでは、互いに要らない二体が同時に動く。今日それを核にしない。今日残すのは、購読がプロンプトの前に来る、である。9/2 のバスFAQを再審しない。バスの分類ではなく、製品の購読である。

対話の種:
「今日の入口は、促か。信号か。」

5. 管理されたハーネスは、ループを製品にする

Agents API の一文は短い。OpenAI がエージェントループを自前の基盤で走らせる。モデル呼び出し、道具、文脈を調整する。能力と、コードとファイルの場所は、利用者が選ぶ。ハーネス、環境、アプリサーバの三片である。ハーネスは環境無しでも動く。環境はホスト、自己、無しである。ホストは用意と接続を製品側が持つ。自己は、用意、再接続、停止、残すファイルを利用者が持つ。

Cursor Projects は、同じ移動を UI にする。開発者をエージェント管理から外し、仕事を指示させる。コーディネータが下位を作り、管理する。必要な数だけ並列に走る。クラウド既定、ローカルは例外である。

なぜ効くか:

  • 自分でループを組むと、圧縮と回復が毎回の仕事になる
  • 管理ハーネスに渡すと、ユニークな能力と環境だけが残る
  • UI のコーディネータと API のセッションは、同じ「ループを渡す」である。同じ入口ではない

今日の角:
料金は、API 自体の追加料金は無い。トークンとツールと、ホスト側なら標準コンテナである。コンテナを無造作に起こすな、という注意がコミュニティにある。公式の本文は、標準コンテナ料金、と書く。無い単価を invent しない。Cursor の 30% と 6 倍は、社内と利用者の公式である。能力点ではない。採用の数字である。9/9 の吸収ROIを今日再審しない。一行の連続である。

対話の種:
「今日渡すのは、プロンプトか。ループか。」
